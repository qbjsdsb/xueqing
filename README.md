# 学情闭环 Xueqing

> 面向教培机构的教学协作与学生成长闭环系统

## 项目状态

**Foundation v0.3｜产品、架构、权限、数据模型与运行风险评审阶段。**

当前仓库已经完成软件正式开发前的核心设计收敛，但 **还不是完整可运行的 Flutter 工程**。`lib/` 只是产品方向的源码占位；下一步应使用当前稳定 Flutter 正式初始化 Windows + Android 工程，并建立 Supabase Development 环境。

> 在安全、权限、备份、真实网络和合规门槛通过前，禁止录入真实学生、家长或教师隐私数据。

## 一句话定位

**不是把 Excel 搬进软件，而是让机构把“发现问题 → 干预 → 验证 → 下一步”变成多人共享、可追溯、低负担的日常教学闭环。**

系统重点回答三个问题：

1. **学生现在最需要解决什么？**
2. **老师下一步应该做什么？**
3. **教学之后，有没有证据表明这个问题已经改善并稳定？**

## 产品核心

### 一份连续学生主档案
同一机构内，一个学生只存在一份主档案。升年级、换老师、换班、换校区都保留历史。

### 多学科学情线
每个学生按学科形成连续学情。任课教师深度访问自己负责的学科，跨学科采用必要共享。

### 学情案例闭环
每个值得独立跟进的问题形成一个 `learning_case`：

**发现 → 确认 → 干预 → 验证 → 稳定观察 → 关闭**

复发时 reopen 原案例，而不是不断复制同一问题。

### 下一步行动驱动
未结束案例通常存在一个当前主行动，例如次课验证、相似题训练或重新讲解；“今日”主要围绕这些行动组织，而不是依赖完整排课系统。

### 事实只记录一次
周度跟进、长期问题提示、阶段指标等从原始教学事实派生，避免教师重复填写。

## V1 首发范围

教师端只保证 4 个核心入口：

- **今日**：到期行动、待验证、重点事项
- **学生**：连续档案、当前重点、时间线
- **课程**：快速开始和完成一次真实教学记录
- **学情**：案例、证据、干预、验证、下一步行动

家校和报告进入 V1.1，不为了“看起来完整”提前铺半成品。

V1 明确不做：
- 收费排课 CRM
- 大型题库
- 成绩预测/学情健康分
- 家长/学生独立 App
- AI 自动正式诊断
- Google Docs 式实时协同
- 复杂离线多主同步

## 总体技术方向

```text
Windows / Android Flutter App
          │
          ├──── 普通授权读写 ─────► Supabase Data API
          │                           └─ PostgreSQL + RLS
          │
          └──── 受控高权限操作 ───► Edge Functions / DB Functions

Supabase Auth     → 登录与会话
Supabase Storage  → 私有附件
GitHub            → 源码、migration、Issue、PR、CI
```

关键边界：
- Flutter 只能持有 Publishable Key；
- Secret/service_role 不进入客户端或 GitHub；
- 业务层通过 Repository / Service 访问后端，不在页面里散落数据库查询；
- RLS 负责“谁能访问”，状态机/多表一致性由事务化业务命令继续约束；
- V1 online-first，但网络失败不能让老师刚填的记录丢失；
- Realtime 只做体验增强，不能成为数据正确性的前提。

## V1 验收重点

V1 不按“页面数量”验收，而按真实流程：

- 两位教师用独立账号看到同一个学生的权限化数据；
- 学生不会因为老师/学科/年级重复建档；
- 一个案例从证据、干预到验证完整可追溯；
- 未结束案例有主行动或暂停理由；
- 常规课后记录中位时间目标 ≤ 60 秒；
- 短暂网络失败不丢正在编辑内容；
- 教师交接不丢历史；
- 跨机构访问在数据库层拒绝；
- View/Function 不能成为绕过 RLS 的后门；
- 非法状态跳转和多表半成功不能破坏数据；
- 数据库和 Storage 都有恢复路径。

## 项目铁律

1. 一个学生只有一份机构主档案。
2. 事实只记录一次，派生信息尽量自动计算。
3. 重要学情结论尽量有证据。
4. 未结束案例有明确下一步行动或暂停理由。
5. 数据归机构，人员变化不能破坏历史。
6. 权限必须在数据库/服务端执行。
7. 状态机和多表不变量不能只靠 Flutter 自觉遵守。
8. 老师少填一次，系统多自动一次。
9. 网络失败不能让高频记录凭空消失。
10. “今日”不能偷偷扩张成收费排课 CRM。
11. AI 只做副驾驶。
