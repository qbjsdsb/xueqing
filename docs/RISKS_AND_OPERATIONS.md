# 风险清单与运行要求

> 本文件记录“如果不提前验证，后期最可能造成返工或上线事故”的事项。风险不是理由停止开发，而是要求在正确时间做验证。

## R1｜Windows / Android 邀请与首次登录体验

**等级：高｜Phase 0 必须验证**

风险：服务端能发邀请，不代表 Windows/Android 上的链接回跳、密码设置、首次激活体验自然。

处理：
- 做真实双平台 Spike；
- 验证邀请、重置密码、Session 恢复；
- 不合格就提前调整认证 UX。

退出条件：两端都能由非技术老师独立完成首次登录。

---

## R2｜真实机构网络环境与 Supabase 可用性

**等级：高｜真实数据前必须验证**

风险：开发者网络正常不等于机构办公网络、教师手机网络都稳定。

处理：
- 实际地点/网络测试登录、查询、上传、Function；
- 记录延迟和失败率；
- Repository/Service 隔离后端细节，避免 UI 全部绑定具体查询。

退出条件：高频教学流程在真实网络下达到可接受稳定性；否则评估区域、代理、后端部署或基础设施替代方案。

---

## R3｜老师不愿意填

**等级：最高｜产品持续验证**

风险：功能再完整，只要课后要填 5 分钟，最终都会变成应付式数据。

处理：
- V1 核心记录 ≤ 60 秒；
- 只记录新事实；
- 周度/阶段自动生成；
- 真实教师可用性测试；
- 统计“完成一次记录的时间与操作数”，而不是统计老师填了多少条。

退出条件：连续一周模拟/试用中，高频流程没有明显填写阻力。

---

## R4｜数据越用越脏

**等级：高**

风险：不同老师自由输入“阅读理解/现代文阅读/阅读”，后期机构统计失去意义。

处理：
- 轻量受控 taxonomy + 自由标题双轨；
- 重复案例提示；
- 管理端允许停用/合并分类节点；
- 不允许删除已有历史所引用的节点。

退出条件：多个教师录入相似问题时仍能落入稳定分类口径。

---

## R5｜权限设计在 UI 看起来对，数据库实际越权

**等级：最高**

风险：隐藏按钮并不阻止手工 API 请求；View/Function 也可能绕过 RLS。

处理：
- RLS + GRANT；
- assignment-based authorization；
- security_invoker View；
- security definer 最小授权；
- 自动化负面权限测试。

退出条件：跨机构、跨学生、跨学科、disabled membership 的攻击式测试全部失败。

---

## R6｜网络失败导致课后记录丢失/重复

**等级：高**

风险：移动网络切换、超时、连点重试可能导致丢数据或重复数据。

处理：
- 本地临时草稿；
- 明确保存状态；
- operation id / idempotency；
- 超时后查询最终状态；
- 不用“乐观 UI”伪造正式保存成功。

退出条件：断网、超时、App 重启场景下输入可恢复且不会重复创建。

---

## R7｜多人更新造成静默覆盖

**等级：中高**

风险：管理员/老师同时修改同一个当前状态对象时，后保存的人覆盖前者。

处理：
- 关键快照对象 `version`；
- 条件更新；
- 冲突提示；
- 教学事实尽量 append-only。

退出条件：模拟两个客户端同时更新时不会静默吞掉一方修改。

---

## R8｜项目悄悄长成 CRM

**等级：高**

风险：为了“今日课程”加入排课，为了排课加入课消，为了课消加入收费，最终偏离核心价值。

处理：
- lesson 定义为教学会话，不是完整 schedule；
- 今日以 case_actions 为主；
- 新增 CRM 类需求必须单独产品评审；
- 优先与已有系统集成，而不是复制所有教务能力。

退出条件：V1 能在没有完整排课系统的情况下完成教师闭环。

---

## R9｜Flutter/Supabase 依赖升级造成不可复现

**等级：中**

处理：
- 正式初始化时锁定当前稳定 Flutter/Dart 基线；
- 提交 `pubspec.lock`（应用项目）；
- CI 使用明确 SDK 版本；
- 升级单独 PR，不和业务功能混在一起；
- 先跑测试再升级 Production。

---

## R10｜Production 与 Development 混用

**等级：最高**

风险：测试脚本误删真实数据、真实学生进入开发截图、Secret 混用。

处理：
- 独立 Supabase project；
- 显著环境标识；
- Production 禁止 seed reset；
- CI/CD 环境变量分开；
- 生产破坏性操作额外确认。

---

## R11｜数据库有备份，但附件没备份

**等级：高**

处理：
- DB 与 Storage 分开设计恢复；
- 定期对象清单；
- 抽样恢复附件；
- 检查 DB path ↔ Storage object 一致性。

---

## R12｜应用分发和更新失控

**等级：中高**

风险：几十个老师各自装不同版本，数据库 schema 已升级但旧客户端仍在使用。

处理：
- Windows/Android 有明确版本号和分发渠道；
- schema 迁移保持必要向后兼容窗口；
- 后期加入最低支持客户端版本提示；
- 签名密钥独立备份。

---

## R13｜自由文本收集过度敏感信息

**等级：高**

处理：
- UI 提示“记录可观察教学事实”；
- 限制日志/AI 输入范围；
- 不把无关家庭/健康推断作为教学标签；
- 管理员可按制度进行更正/删除/导出。

---

## R14｜AI 让数据看起来更漂亮，但事实变差

**等级：中高（V2）**

处理：
- AI 输出先是 draft；
- 保留来源与人工确认；
- AI 不写正式 status；
- AI 不把自己的总结当 evidence；
- AI 不越权跨学科读取。

---

# 真实数据上线前 Go / No-Go 清单

必须全部满足才进入真实学生数据：

- [ ] 仓库已 Private 或完成等价源码访问控制
- [ ] Development / Production 已隔离
- [ ] 双平台认证流程验证
- [ ] RLS/GRANT/View/Function 越权测试通过
- [ ] 网络失败草稿恢复通过
- [ ] 实际机构网络测试通过
- [ ] 教师交接通过
- [ ] 数据库恢复演练通过
- [ ] Storage 恢复方案存在并抽测
- [ ] Production Secret 不在客户端/GitHub
- [ ] 日志无敏感正文和 Token
- [ ] 安装包签名与更新路径明确
- [ ] 根据实际部署地区完成隐私/未成年人数据合规评估

只要其中关键项未满足，就继续使用虚构/脱敏数据。
