# Xueqing UX Copy

状态：Phase 0A.5 copy baseline

最后更新：2026-09-02

文案面向正在上课、备课或复盘的教师。优先告诉教师“现在是什么、下一步做什么、失败后怎么办”，不使用宣传册语气，也不把未经证实的推断写成事实。

## 1. 语气

- 短、具体、平静；用动作和事实，不用鼓励式口号。
- 优先中文动词：查看、记录、补充、确认、完成、重新打开、安排。
- status 用“待验证/已逾期/待安排”等可执行词，不用“风险高/需要赋能”。
- 允许温度，但不幼态；不称呼学生为标签或分数。
- 失败时先说明内容是否保留，再说明恢复动作。

## 2. 核心词汇表

| 推荐 | 含义/用法 | 避免 |
| --- | --- | --- |
| 今日 | 当前工作队列 | Dashboard、工作驾驶舱 |
| 学生 | 学生查找与理解入口 | 客户、用户 |

| 学情 | Learning Case 与跟进入口 | 数据中心 |

## 4. State copy rules

### Loading

- `正在加载今日事项…`
- `正在打开学生详情…`
- `正在读取这条 Case…`

加载不显示空列表或“没有数据”，避免把 loading 误读成 empty。

### Empty

空状态说明对象和下一步，不使用“暂无数据”作为唯一文案。例如：`还没有待验证事项。完成一次检查后，在这里确认是否稳定。`

### Error

- `今日事项暂时加载失败。可以重试，已有本地内容不会被删除。`
- `学生详情暂时打不开。请重试；如果仍失败，稍后再打开。`
- `保存失败，刚才的内容还在。`

### Permission

- `当前账号无权查看这名学生的学情内容。`
- `你可以查看摘要，但不能修改此学科内容。`
- `这个动作需要负责该学科的教师权限。`

权限文案不泄露被隐藏对象的标题、姓名或数量。

## 5. Button hierarchy

每个上下文最多一个 primary action；secondary action 使用 outline/text button，危险操作明确写出结果。

| 类型 | 推荐文案 | 例 |
| --- | --- | --- |
| Primary | 具体动词 | 记录问题、确认稳定、完成行动 |
| Secondary | 查看/补充/稍后 | 查看 Case、补充证据、稍后整理 |
| Destructive | 说明对象与结果 | 放弃记录、重新打开（如果这是状态变化） |
| Retry | 重试 | 保存失败、加载失败 |

避免“确定”“提交”“开始使用”等缺少对象的通用词，除非对话框标题已经说明对象且无歧义。

## 6. 状态与颜色的文案冗余

任何状态都至少同时具备：可读文本 + 结构位置或图标 + 可执行动作（若存在）。

- `已逾期`：文字 + 日期 + 补救 action。
- `待验证`：文字 + 待确认动作；不用“通过”代替。
- `稳定`：文字 + 下次检查 action；不用绿色勾选表示 closed。
- `离线草稿`：文字说明是否计入正式学情；不用灰色小点代替。

## 7. Fixture 与调试文案

prototype 的非业务信息统一使用：`设计预览 · 虚构数据 · 无后端连接`。不得出现真实学生姓名、真实联系方式、看似真实的成绩或“AI 建议”。这些文字不能进入生产组件。
