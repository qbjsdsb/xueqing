# Xueqing UX Copy

状态：教师可读性收口基线

最后更新：2026-09-08

文案面向正在上课、备课或复盘的教师。优先告诉教师“现在是什么、下一步做什么、失败后怎么办”，不使用宣传册语气，也不把未经证实的推断写成事实。

## 1. 语气

- 短、具体、平静；用动作和事实，不用鼓励式口号。
- 教师可见界面优先使用自然中文：查看、记录、补充、处理、检查、提醒、结束跟进。
- 数据库、代码和开发文档可以继续使用 Case / Evidence / Intervention / Assessment / Action 等内部术语，但这些词默认不得直接暴露给普通教师。
- 状态使用“待验证 / 已逾期 / 待安排”等可执行词，不使用“风险高 / 需要赋能”。
- 允许温度，但不幼态；不称呼学生为标签或分数。
- 失败时先说明内容是否保留，再说明恢复动作。

## 2. 核心教师语言

| 教师界面推荐 | 内部概念 | 避免直接展示 |
| --- | --- | --- |
| 今日 | 当前工作队列 | Dashboard、工作驾驶舱 |
| 学生 | 学生查找与理解入口 | 客户、用户 |
| 课程 | 一次教学记录入口 | 排课中心、课时管理 |
| 学情 | 问题与持续跟进入口 | 数据中心 |
| 跟进问题 / 问题 | Learning Case | Learning Case、Case、工单、风险卡 |
| 学生表现 / 观察记录 | Evidence | Evidence、证据链、智能洞察 |
| 教师判断 | 对事实的解释 | AI 分析、自动结论 |
| 教学处理 | Intervention | Intervention、赋能方案 |
| 检查结果 | Assessment / Verification | Assessment、Verification、成长指数 |
| 下一步 / 提醒 | Next Action | Next Action、Action、推荐任务 |
| 待验证 | 检查已发生，仍待教师判断 | pending verification、通过即解决 |

## 4. 教师可读时间线

时间线不是数据库事件日志。它的目标是让接手教师快速理解“发生过什么”。

### 4.1 展示原则

- 一次教师操作尽量只展示一条可读记录；底层可以保留多条审计事件。
- 同一次操作产生的“检查结果 + 完成当前提醒 + 暂时稳定 + 结束跟进”等技术事件，在教师时间线上聚合成一条自然语言记录。
- Evidence / Intervention / Assessment 本体与对应 case event 不能重复展示两次。
- 默认最新在前；按日期分组；同一天内按发生时间排序。
- 时间线只展示教学事实和有意义的状态变化，不展示 operation id、version、内部 event key 等工程字段。
- 学生页“最近记录”和问题详情必须使用同一套教师可读记录，不得各自拼一套历史。

### 4.2 推荐记录类型

- `发现问题`
- `学生表现`
- `教师判断`
- `教学处理`
- `检查结果`
- `设置提醒`
- `调整提醒`
- `结束跟进`
- `重新跟进`

### 4.3 示例

```text
9月8日 19:40  发现问题
现代文概括题经常漏答要点
具体表现：能找到原文，但答案经常只写一个方面

9月10日 18:20  教学处理
重新练习“圈关键词 → 分层 → 合并答案”
下一步：9月12日再检查

9月12日 20:05  检查结果 · 部分改善
能答出两个方面，但概括仍不够准确
继续观察

9月19日 19:50  检查结果 · 达到预期
连续两次独立完成
结束跟进
```

## 5. 导出文案

| 场景 | 文案 |
| --- | --- |
| 学生+学科导出 | `导出学情记录` |
| 老师导出 | `导出教学记录` |
| 生成中 | `正在生成记录表…` |
| 成功 | `记录表已生成。` |
| 取消保存 | `已取消导出。` |
| 失败 | `导出失败，请重试。` |
| 无记录 | `当前没有可导出的记录。` |

导出表与应用时间线使用同一套教师可读记录语义。禁止把数据库事件日志原样倒入 Excel。

## 6. 状态文案

### Loading

- `正在加载今日事项…`
- `正在打开学生详情…`
- `正在读取这条问题记录…`

加载不显示空列表或“没有数据”，避免把 loading 误读成 empty。

### Empty

空状态说明对象和下一步，不使用“暂无数据”作为唯一文案。例如：`还没有待验证事项。记录一次检查后，会在这里出现。`

### Error

- `今日事项暂时加载失败。可以重试，已有本地内容不会被删除。`
- `学生详情暂时打不开。请重试。`
- `保存失败，刚才的内容还在。`

### Permission

- `当前账号无权查看这名学生的学情内容。`
- `你可以查看，但不能修改这门学科的记录。`
- `这个动作需要当前合法的教学权限。`

权限文案不泄露被隐藏对象的标题、姓名或数量。

## 7. Button hierarchy

每个上下文最多一个 primary action；secondary action 使用 outline/text button，危险操作明确写出结果。

| 类型 | 推荐文案 | 例 |
| --- | --- | --- |
| Primary | 具体动词 | 记录问题、记录进展、处理 |
| Secondary | 查看/补充/导出 | 查看问题、补充学生表现、导出学情记录 |
| Destructive | 说明对象与结果 | 放弃记录、结束跟进 |
| Retry | 重试 | 保存失败、加载失败 |

避免“确定”“提交”“开始使用”等缺少对象的通用词，除非对话框标题已经说明对象且无歧义。

## 8. Fixture 与调试文案

prototype 的非业务信息统一使用：`设计预览 · 虚构数据 · 无后端连接`。不得出现真实学生姓名、真实联系方式、看似真实的成绩或“AI 建议”。这些文字不能进入生产组件。
