# Xueqing UX Copy

状态：教师可读性收口基线

最后更新：2026-09-08

文案面向正在上课、备课或复盘的教师。优先告诉教师“现在是什么、下一步做什么、失败后怎么办”，不使用宣传册语气，也不把未经证实的推断写成事实。

## 1. 语气

- 短、具体、平静；用动作和事实，不用鼓励式口号。
- 教师可见界面优先使用自然中文：查看、记录、补充、处理、检查、提醒、结束跟进。
- 数据库、代码和开发文档可以继续使用 Case / Evidence / Intervention / Assessment / Action 等内部术语，但这些词默认不得直接暴露给普通教师。
- 状态使用“跟进中 / 继续关注 / 已逾期 / 待安排”等可理解词，不使用“风险高 / 需要赋能”。
- 允许温度，但不幼态；不称呼学生为标签或分数。
- 失败时先说明内容是否保留，再说明恢复动作。

### 1.1 记录不是任务

- 教师随手记录一条学生情况，只表示“这件事发生过”，不得自动制造 Today 待办。
- 只有教师明确设置提醒，或已经存在明确 Action 时，Today 才把它视为需要处理的工作。
- 教师负责表达事实和判断，系统负责维护 Case / Evidence / Event / status 等底层结构。
- 任何可选字段都不得为了“数据完整”阻断课堂记录。

## 2. 核心教师语言

| 教师界面推荐 | 内部概念 | 避免直接展示 |
| --- | --- | --- |

## 3. 页面文案

### 今日

Today 只承担“老师明确承诺要处理什么”的责任，不承担“所有还没整理的数据”的责任。

| 场景 | 文案 |
| --- | --- |
| 页面标题 | `今日` |
| 页面说明 | `先处理今天要做的事，再回看最近学生。` |
| 今天到期 | `今天到期` |
| 逾期 | `已逾期` |
| 未来提醒 | `之后要处理` |
| 无日期提醒 | `待安排` |
| 最近学生 | `最近学生` |
| 直接处理 | `处理` |
| 进入上下文 | `查看学生` / `查看问题` |
| 同一学生更多事项 | `还有 {count} 项` |
| 全部完成 | `今天暂时没有需要处理的事项。` |
| 无明确任务 | `可以回看最近学生，或在课堂中随手记下一条新情况。` |

以下内容**不得仅因其状态自动进入 Today**：

- 没有 Action 的新记录；
- 刚完成一次检查、但教师没有设置新提醒的记录；
- 仅仅因为底层 status 尚未关闭的 Case。

### 学生详情

| 场景 | 文案 |
| --- | --- |
| 页面说明 | `先看当前重点，再按需要展开历史。` |
| 重点标题 | `现在最重要的事` |
| 全部问题标题 | `全部问题` |
| 展开全部 | `查看全部 {count} 个` |
| 收起全部 | `只看重点` |
| 额外关注标题 | `另外需要关注` |
| 学生列表有当前问题 | `{count} 个跟进中的问题` |
| 学生列表无当前问题 | `暂无需要跟进的问题` |
| 完全没有问题记录 | `还没有记录的问题。发现情况时，可以先记下来。` |
| 只有结束历史 | `当前没有需要跟进的问题。以前的记录仍然保留，需要时可以查看。` |
| 最近记录 | `最近记录` |
| 记录问题 | `记录问题` |
| 可查看不可编辑 | `你可以查看，但不能修改这门学科的记录。` |
| 无权限 | `当前账号无权查看这名学生的学情内容。` |
| 导出 | `导出学情记录` |

学生详情不重复铺设多份完整问题列表。结束的问题不计入“当前问题”数量；历史只用于解释现在。

| 检查段 | `检查结果` |
| 下一步段 | `当前提醒` |

| 检查后继续观察 | `继续关注` |

| 稳定历史 | `目前表现稳定。` |
| 已结束 | `已结束跟进。历史记录完整保留。` |

| 加判断 | `记录教师判断` |

### 记录问题

课堂入口只问当前真正需要教师回答的内容。

| 场景 | 文案 |
| --- | --- |
| 标题 | `记录问题` |
| 已知学生上下文 | `{学生名} · {学科}` |
| 全局入口需要选择 | `学生` |
| 唯一主输入 | `今天发现什么？` |
| placeholder | `例如：阅读题经常漏看限制词。今天连续两题都没注意“不正确的是”。` |
| 可选展开 | `更多选项` |
| 分类 | `问题类型（可选）` |
| 图片 | `现场照片（可选）` |
| save | `记录问题` |
| cancel | `取消` |
| saved | `已记录到学生成长记录。` |
| failed | `保存失败，刚才的内容还在。` |
| retry | `重试` |
| dirty close | `还没有保存，要放弃这段记录吗？` |
| discard | `放弃记录` |

课堂快速记录最小输入为：`已知学生/学科上下文 + 一句话`。一句完整的话同时作为首次事实依据；系统可从首句生成内部问题标题，教师不需要把同一件事写两遍。问题类型、图片、提醒、根因、教师判断和教学方案都不得成为课堂记录的必填条件。

### 记录进展

默认只展示：

1. 当前问题；
2. `这次有什么新情况？`；
3. `保存记录`。

`补充记录方式（可选）`再展开“新表现 / 教学处理 / 检查结果”；`需要提醒或结束跟进？`再展开“继续观察 / 设置提醒 / 结束跟进”。默认保存不生成新待办。

记录“检查结果”时，检查结果本身是有效事实；补充说明可以选填。系统不得为了形成漂亮闭环而要求教师额外编写一段文字。

## 4. 教师可读时间线

时间线不是数据库事件日志。它的目标是让接手教师快速理解“发生过什么”。

### 4.1 展示原则

- 一次教师操作尽量只展示一条可读记录；底层可以保留多条审计事件。
- 同一次操作产生的“检查结果 + 完成当前提醒 + 状态变化 + 结束跟进”等技术事件，在教师时间线上聚合成一条自然语言记录。
- Evidence / Intervention / Assessment 本体与对应 case event 不能重复展示两次。
- 新的一句话 Quick Capture 若 description 与首条 Evidence 内容相同，只展示一次，不再重复拼“问题标题 + 具体表现”。
- 默认最新在前；按日期分组；同一天内按发生时间排序。
- 时间线只展示教学事实和有意义的状态变化，不展示 operation id、version、内部 event key 等工程字段。
- 学生页“最近记录”和问题详情必须使用同一套教师可读记录，不得各自拼一套历史。

### 4.2 推荐记录类型

- `发现问题`
- `学生表现`
- `教师判断`
- `教学处理`
- `检查结果`
- `设置提醒`
- `调整提醒`
- `结束跟进`
- `重新跟进`

### 4.3 示例

```text
9月8日 19:40  发现问题
阅读题经常漏看限制词。今天连续两题都没注意“不正确的是”。

9月10日 18:20  教学处理
重新练习“圈限制词 → 带题干定位 → 再作答”

9月12日 20:05  检查结果 · 部分通过
能主动圈限制词，但独立完成时仍会漏一次

9月19日 19:50  检查结果 · 通过
连续两次独立完成
结束跟进
```

## 5. 导出文案

| 场景 | 文案 |
| --- | --- |
| 学生+学科导出 | `导出学情记录` |
| 老师导出 | `导出教学记录` |
| 生成中 | `正在生成记录表…` |
| 成功 | `记录表已生成。` |
| 取消保存 | `已取消导出。` |
| 失败 | `导出失败，请重试。` |
| 无记录 | `当前没有可导出的记录。` |

导出表与应用时间线使用同一套教师可读记录语义。禁止把数据库事件日志原样倒入 Excel。

## 6. 状态文案

### Loading

- `正在加载今日事项…`
- `正在打开学生详情…`
- `正在读取这条问题记录…`

加载不显示空列表或“没有数据”，避免把 loading 误读成 empty。

### Empty

空状态说明对象和下一步，不使用“暂无数据”作为唯一文案。例如：`今天暂时没有需要处理的事项。可以回看最近学生，或随手记一条新情况。`

### Error

- `今日事项暂时加载失败。可以重试，已有本地内容不会被删除。`
- `学生详情暂时打不开。请重试。`
- `保存失败，刚才的内容还在。`

### Permission

- `当前账号无权查看这名学生的学情内容。`
- `你可以查看，但不能修改这门学科的记录。`
- `这个动作需要当前合法的教学权限。`

权限文案不泄露被隐藏对象的标题、姓名或数量。

## 7. Button hierarchy

每个上下文最多一个 primary action；secondary action 使用 outline/text button，危险操作明确写出结果。

| 类型 | 推荐文案 | 例 |
| --- | --- | --- |
| Primary | 具体动词 | 记录问题、保存记录、处理 |
| Secondary | 查看/补充/导出 | 查看问题、补充学生表现、导出学情记录 |
| Destructive | 说明对象与结果 | 放弃记录、结束跟进 |
| Retry | 重试 | 保存失败、加载失败 |

避免“确定”“提交”“开始使用”等缺少对象的通用词，除非对话框标题已经说明对象且无歧义。

## 8. Fixture 与调试文案

prototype 的非业务信息统一使用：`设计预览 · 虚构数据 · 无后端连接`。不得出现真实学生姓名、真实联系方式、看似真实的成绩或“AI 建议”。这些文字不能进入生产组件。
