# Xueqing V0.2 角色权限合同

本文件冻结首个 Stable 候选采用的三角色权限边界，避免后续 UI、RLS、RPC 或测试再次产生不同理解。

## 负责人 `org_owner`

负责人拥有机构内完整权限：

- 查看并操作全机构 `今日 / 学生 / 学情 / Learning Case`；
- 创建和推进 Case、Evidence、Action、Assessment 等教学闭环；
- 管理学生、学科、任课范围和学生任课分配；
- 查看成员与邀请；
- 邀请成员、处理邀请、停用/恢复成员以及受控账号凭据操作。

## 管理员 `org_admin`

管理员拥有机构业务与教学闭环的全机构权限，但不拥有成员账号生命周期写权限：

- 可以查看并操作全机构 `今日 / 学生 / 学情 / Learning Case`；
- 可以管理学生、学科、任课范围和学生任课分配；
- 可以查看成员和邀请状态；
- 不能创建、审批、撤销或重新发放成员邀请；
- 不能停用或恢复成员；
- 不能通过受控服务端路径重发其他成员凭据。

## 老师 `teacher`

老师的学生与学情访问继续由有效任课关系和教学学科范围共同约束：

- 只能访问自己当前合法任课范围内的学生与学情；
- 任课关系或教学范围结束后，相关访问与写权限必须立即失效；
- 不因普通教师身份获得机构级读取能力。

## 不可突破的边界

- 任何角色都不能跨机构访问数据；
- 已停用成员和失效会话必须 fail closed；
- UI 隐藏或禁用按钮只是体验层，数据库 RLS 和受保护 RPC 才是最终安全边界；
- 负责人/管理员的机构级学情权限不能破坏老师原有的任课隔离；
- 测试必须同时覆盖正向权限和拒绝路径。
