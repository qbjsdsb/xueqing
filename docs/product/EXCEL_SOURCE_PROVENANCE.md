# Excel / Leadership Source Provenance｜来源与归因分级

> 状态：Phase 0A.6 evidence discipline。目的：避免把“源 Word/领导理念”“Excel 化时新增管理建议”“Xueqing 软件工程增强”混成同一层事实。

## 1. 为什么必须分级

用户提供的文件本身标题是：

> `单科学员学情档案｜Excel 化原型 v0.1（审校版）`

其 `00_说明与规则` 明确说明：
- Excel 依据一个更早的 Word 文件重组；
- 当前版用于确认方向，不代表最终定稿；
- 部分字段是 Excel 化时新增的管理建议，需老板确认；
- 当前“一工作簿一学生一学科”只是原型假设；
- 如果做全机构集中管理，需要升级为学生主表 + 明细台账。

因此 Phase 0A.6 不能把 Excel 每个列名都称为“领导原始理念”。

---

## 2. Evidence Level L1｜可确认属于源教学方法骨架

根据 Excel `00_说明与规则` 对源 Word 的映射，可以高置信确认原方法包含七个核心部分：

1. 学生基础档案；
2. 三类问题初诊；
3. 知识问题三阶闭环；
4. 每周迭代学情记录；
5. 顽固问题跨周台账；
6. 家校沟通记录；
7. 阶段复盘长文本与签字。

核心业务链在 Excel 中被明确概括为：

`学生档案 → 初诊问题 → 三阶知识闭环 → 周度跟进 → 顽固问题 → 家校沟通 → 阶段复盘`

这条链可以作为“领导教学方法/源方案”的高置信骨架。

---

## 3. Evidence Level L1｜明确源方法语义

### 三类问题
Excel 明确说明源 Word 的三类问题为：
- 知识漏洞；
- 学习习惯；
- 考试技巧。

### 三阶知识闭环
Excel 明确源逻辑：

`当堂订正 → 课后相似题巩固 → 次课小测 → 清零/跨周跟进`

### 顽固问题
Excel 明确：

> 只放多次整改仍未通关的问题。

### 家校
Excel 明确目的：

> 同步学生整改进度，反馈三阶订正结果，布置家校配合任务。

### 阶段复盘
源方案包含：
- 阶段整体进步；
- 遗留问题；
- 下一阶段计划；
- 授课老师签字/日期语义。

这些可以直接用于教学方法论翻译。

---

## 4. Evidence Level L2｜Excel 原型保留/结构化后的口径

以下内容可能源于 Word，但当前能直接看到的是 Excel 审校版的结构化表达；在称为“领导原话/原始字段”前应谨慎：

- 学情定位的四档下拉；
- 各三阶阶段的具体下拉措辞；
- 周度复盘的状态下拉；
- 顽固问题最终状态措辞；
- 档案状态等结构化选项。

这些非常适合作为**产品输入参考**，但不应未经确认就硬编码为不可变数据库 enum。

---

## 5. Evidence Level L3｜Excel 化时明确新增的管理建议

`00_说明与规则` 直接说明以下属于新增字段/管理建议，不是源 Word 原样字段，需老板确认：

- 问题编号；
- 优先级；
- 当前状态；
- 责任人；
- 下次跟进日期；
- 记录人；
- 等类似管理字段。

因此：

### 可以采用
如果它们确实提升多人机构协作，例如：
- owner；
- action due time；
- created_by；
- stable IDs；

Xueqing 可以采用。

### 但必须正确归因
它们属于：

> **对领导教学方法的软件化/管理增强**

而不是：

> “领导原来就要求每个问题必须有这个字段”。

---

## 6. Evidence Level L3｜Excel 原型自己的技术假设

当前原型假设：

> 一个工作簿对应一个学生的一门学科。

Excel 自己已经写明：若老板需要全校/全年级汇总，应改成多学生集中模型。

所以 Xueqing 采用：
- 机构统一 Student；
- Student Subject Profile；
- teacher/staff assignment；

不是背离 Excel，而是 Excel 自身已经预见的产品化升级方向。

---

## 7. Evidence Level L3｜阶段摘要指标不是必须继承的领导 KPI

`07_阶段复盘` 当前 Excel 增加了：
- 初诊问题总数；
- 初诊已清零数；
- 跨周跟进记录数；
- 家校沟通次数。

说明页写明阶段复盘被“增加可追溯的摘要指标”，且原型边界明确不擅自加入复杂评分/dashboard。

> **原型核验说明（只读）**：附件《学情档案Excel化原型_v0.1_修复版.xlsx》的 `07_阶段复盘` 摘要计数区域实际保存为静态 `0` 值；对工作簿 XML 的只读检查未发现对应公式节点。因此本阶段文档把这些单元格明确视为 **static prototype placeholders / demonstration values**，不能描述为 Excel 已经存在的自动计算逻辑。后续若要引入公式，必须另行提交原型变更并独立核验，不扩大本 Phase 0A.6 文档修复范围。

因此这些计数：
- 可以用于原型检查；
- 不应自动升级成 Xueqing 管理 KPI；
- 特别是“沟通次数”“老师填多少条”不得作为教师绩效核心指标。

Xueqing 优先展示可处理异常与闭环事实。

## 8. Evidence Level X｜Xueqing 自己的产品/工程增强

下列属于 Xueqing 根据真实多人云软件需求新增，不应归因给领导原 Word：

- organization / membership / role / RLS；
- teacher subject scope；
- Lead / Collaborator；
- Advisor 权限；
- Case 六态 lifecycle；
- Next Action 不变量；
- version / expected_version；
- operation_id / idempotency；
- secure Session / revoked token guard；
- encrypted local draft；
- student merge；
- handoff；
- finalized snapshot；
- cloud provider portability；
- backup/restore；
-治理异常。

它们的价值是：

> **让领导方法在多人、长期、云端环境中真正可执行，而不是改变教学方法本身。**

---

## 9. 产品沟通规则

以后向领导介绍时建议使用三层语言：

### “您原来方法里已经有”
仅用于 L1 高置信内容。

### “我们把原来的做法软件化成”
用于 L2/L3 的产品转译，例如 owner、下一步、状态、自动提醒。

### “为了多人协作和数据安全，我们额外增加”
用于 Xueqing 工程增强，例如权限、交接、并发、备份。

避免说：

> “这是您 Excel 要求的。”

如果其实只是原型新增字段。

---

## 10. 当前冻结结论

- 领导/源方法的高置信核心是七段教学闭环，而不是所有 Excel 列名。
- Excel 自身就是过渡原型，不是最终产品 schema。
- 新增管理字段可以保留，但要以产品价值论证，而不是靠“领导原要求”背书。
- Xueqing 的权限/云端/并发/治理属于必要软件工程增强，应明确区分来源。
