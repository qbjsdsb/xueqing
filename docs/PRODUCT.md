# 产品蓝图

## 1. 产品名称

**学情闭环**

副标题：机构教学协作与学生成长管理平台

## 2. 产品目标

让机构内部所有老师围绕同一份学生成长档案协作，并通过可追踪、可验证的教学闭环，把“发现问题—教学干预—再次检测—稳定解决”沉淀为机构长期资产。

## 3. 核心对象

### 学生主档案

一个学生在同一机构内只有一份主档案。升年级、换老师、换班级、换校区都不重新建档。

### 学科学情线

学生主档案下按学科形成连续学情线。各学科教师默认看到本科目详细信息，跨学科只共享必要摘要与综合观察。

### 学情案例

学情案例是教学闭环的最小业务单元，包括：

- 问题是什么
- 首次何时发现
- 有什么证据
- 老师如何判断原因
- 采取了什么教学干预
- 何时进行检测
- 结果如何
- 是否复发
- 下一步行动是什么

## 4. 学情状态机

新发现 → 已确认 → 干预中 → 待验证 → 已稳定 → 已关闭

若后续复发，可重新打开原案例，而不是无限重复新建。

长期反复问题通过规则自动提示“重点问题/顽固问题”，由教师确认后进入原因复盘。

## 5. 教师端一级入口

1. 今日：今天需要做什么
2. 学生：这个学生现在怎么样
3. 课程：今天上了什么
4. 学情：哪些问题还没有解决
5. 家校：如何向家长反馈
6. 报告：阶段内发生了什么变化

## 6. 管理端关注点

管理端重点展示教学异常、学生风险、长期未解决问题、高频共性问题与教研机会，不把系统设计为纯粹的教师填表 KPI 工具。

## 7. 核心使用流程

### 课前

系统自动展示上次遗留问题、待验证问题、本次建议行动。

### 课中

教师快速记录：通过 / 部分通过 / 未通过；必要时新增问题或证据。

### 课后

点击完成课程后自动：

- 更新问题状态
- 形成教学时间轴
- 生成下次待办
- 汇总周度数据
- 生成家长反馈草稿

目标：常规课后记录尽量在 30–60 秒内完成。

## 8. 跨学科协作

采用“默认隔离、必要互通”：

- 本科教师：本科详细学情可见可编辑
- 其他学科教师：默认只见综合摘要、关键观察与必要风险
- 班主任/学管：跨学科综合视角
- 学科负责人：本科组范围
- 教务/管理员：按机构权限查看

## 9. 产品铁律

1. 一个学生只有一份机构主档案。
2. 原始事实只录入一次，派生数据自动计算。
3. 重要结论尽量有证据。
4. 未解决问题必须有下一步行动。
5. 老师少填一次，系统多自动一次。
6. AI 只辅助，不静默替老师下结论。
7. 数据归机构，教师离职后历史完整保留。
