# Excel 原型到软件模型的转换

## 1. 来源

本项目的业务原型来自《学情档案Excel化原型_v0.1_修复版.xlsx》。原型包含：

- `00_说明与规则`
- `01_学生档案`
- `02_初诊问题`
- `03_知识闭环`
- `04_周度跟进`
- `05_顽固问题`
- `06_家校沟通`
- `07_阶段复盘`

Excel 的设计目标是把 Word 模板变成可筛选、可持续追加的数据表；软件的目标则进一步变成“只录原始事实，系统自动组织闭环”。因此不能一张 Sheet 对应一个页面或一张数据库表。

## 2. 总体转换原则

### Excel 时代
为了方便人工查看，数据会重复出现在：
- 初诊台账
- 知识闭环
- 周度跟进
- 顽固问题
- 阶段复盘

### 软件时代
同一事实只保存一次：

```text
学生
  ↓
学科学情档案
  ↓
学情案例
  ├─ 证据
  ├─ 干预
  ├─ 验证
  ├─ 下一步行动
  └─ 案例事件时间轴

课程 / 观察 / 家校沟通
  ↓
系统自动生成周度与阶段摘要
```

## 3. 各 Sheet 的软件归宿

### `00_说明与规则`
**不进入业务数据库。**

转化为：
- 产品规则文档；
- 字典/枚举说明；
- 表单帮助文字；
- 管理员配置；
- 开发约束。

### `01_学生档案`
原字段包括姓名、学科、年级、老师、建档日期、频次、联系方式、学情定位、优势、档案状态等。

软件拆分为：
- `students`：学生稳定身份；
- `student_enrollments`：年级/校区/班级历史；
- `guardians + student_guardians`：家长联系关系；
- `student_subject_profiles`：单科学情线；
- `student_teacher_assignments`：教师负责历史。

关键改变：年级和授课老师都不能只保存“当前值”，否则升年级或换老师后历史丢失。

### `02_初诊问题`
原字段：问题编号、问题分类、具体表现、根本原因、整改方案、优先级、状态、首次发现日期、责任人。

软件核心映射：
- `learning_cases`
- 首次证据 `case_evidence`
- 当前负责人 `owner_membership_id`
- 第一个 `case_action`

原来的“知识漏洞 / 学习习惯 / 考试技巧”保留为 `case_type`，但不限制未来增加其他类型。

### `03_知识闭环`
原有三阶逻辑：

**当堂订正 → 课后相似题 → 次课小测 → 清零 / 跨周**

软件不做一张“三阶表”，而是拆成：
- 当堂订正 → `interventions`
- 相似题巩固 → `interventions` 或 `case_actions`
- 次课小测 → `assessments`
- 每次状态变化 → `case_events`
- 未通过后的下次动作 → 新 `case_action`

这样既保留三阶教学理念，又允许不同类型问题采用不同干预路径。

### `04_周度跟进`
原 Excel 一行一周，记录授课内容、旧问题整改、新问题、整改动作、复盘、下周重点。

**软件中不再要求教师重新填一份周表。**

系统从：
- lessons
- learning_cases
- case_events
- interventions
- assessments
- observations
- case_actions

自动生成周度摘要。

只有老师真正想补充的“本周综合判断”才允许作为可选评论，而不是必填。

### `05_顽固问题`
原 Excel 维护第二份“顽固问题跨周台账”。

软件中取消独立事实表。

规则可提示某 learning_case 成为重点/长期问题，例如：
- 30 天内多次失败；
- 连续多次验证未通过；
- stable/closed 后再次 reopen；
- 超过一定时间仍未结束。

由教师确认“重点问题”标签，并触发原因复盘。

好处：不会出现初诊表写“已解决”、顽固表还写“跟进中”的冲突。

### `06_家校沟通`
映射为 `parent_communications`。

联系方式不在每次沟通记录中复制，统一引用 guardian。

沟通内容可以关联：
- learning_case
- report
- lesson
- observation

但 V1 不要求建立复杂关系图，先保留学生级沟通事实。

### `07_阶段复盘`
原 Excel 上方指标 + 三段总结文字。

软件拆成：
- 指标：从事实表自动计算；
- 总结：生成 report draft；
- finalized 报告：保存冻结快照；
- 下一阶段重点：转化为未完成 case_actions 或新/既有 learning_cases。

报告不能成为另一套需要手工同步的“总台账”。

## 4. Excel 中值得保留的教学思想

必须保留：
- 三类问题初诊；
- 问题编号/可追踪思想；
- 三阶订正与再检测；
- 跨周跟进；
- 顽固问题原因复盘；
- 家校沟通；
- 阶段复盘；
- 不用未经验证的复杂评分体系。

需要软件化改造：
- 一工作簿一学生 → 机构统一学生主档案；
- 一行一周 → 自动周度汇总；
- 顽固问题第二台账 → 同一案例的派生状态；
- 固定三阶列 → 事件化干预/检测流程；
- “老师”当前值 → 教师 assignment 历史；
- “年级”当前值 → enrollment 历史。

## 5. V1 不做自动导入真实 Excel

第一阶段先把数据库和工作流跑对，再开发 Excel 导入器。

原因：
- 原型假设“一工作簿一学生一学科”；
- 软件模型已经拆分为多个关联对象；
- 过早写导入器会把临时字段结构固化进正式数据库。

等 V1 schema 稳定后，再做：
1. Excel 预览；
2. 字段映射；
3. 学生查重；
4. 导入校验；
5. 导入报告与回滚。

## 6. 产品验收问题

每增加一个页面或数据库表，都应该问：

> 这是不是一个新的真实业务事实？

如果只是“另一种总结、另一种视图、另一种周期统计”，优先做成查询/视图/报告，不要再让老师填写一遍。
