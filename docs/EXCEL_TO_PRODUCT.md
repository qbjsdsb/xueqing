# Excel 原型到软件模型的转换

## 1. 来源

本项目的业务原型来自《学情档案Excel化原型_v0.1_修复版.xlsx》。原型包含：

- `00_说明与规则`
- `01_学生档案`
- `02_初诊问题`
- `03_知识闭环`
- `04_周度跟进`
- `05_顽固问题`
- `06_家校沟通`
- `07_阶段复盘`

Excel 的目标是把 Word 模板变成可筛选、可持续追加的数据表；软件的目标进一步变成：**只录真正发生的事实，系统自动组织闭环和下一步。**

因此不能一张 Sheet 对应一个页面或一张数据库表。

## 2. 总体转换原则

### Excel 时代
为了人工查看，同一件事情容易重复出现在：
- 初诊台账
- 知识闭环
- 周度跟进
- 顽固问题
- 阶段复盘

### 软件时代
同一事实只保存一次：

```text
学生主档案
  ↓
学生学科档案
  ↓
学情案例
  ├─ 受控分类 + 自由描述
  ├─ 证据
  ├─ 干预
  ├─ 验证
  ├─ 下一步主行动
  └─ 案例事件时间轴

课程 / 综合观察 / 家校沟通
  ↓
系统生成周度与阶段摘要
```

## 3. 各 Sheet 的软件归宿

### `00_说明与规则`
**不进入业务数据库。**

转化为：
- 产品规则；
- 字典/枚举；
- taxonomy；
- 表单帮助文字；
- 管理员配置；
- 开发约束。

### `01_学生档案`
原字段包括姓名、学科、年级、老师、建档日期、频次、联系方式、学情定位、优势、档案状态等。

软件拆分为：
- `students`：学生稳定身份；
- `student_enrollments`：年级/校区/班级历史；
- `student_subject_profiles`：单科学情线；
- `student_teacher_assignments`：任课教师负责历史；
- `student_staff_assignments`：学管/班主任等非学科责任历史；
- `guardians + student_guardians`：家长联系关系（V1.1 按需）。

关键改变：年级和负责人都不能只保存“当前值”，否则升年级或换老师后历史丢失。

### `02_初诊问题`
原字段：问题编号、问题分类、具体表现、根本原因、整改方案、优先级、状态、首次发现日期、责任人。

软件核心映射：
- `learning_cases`
- `learning_taxonomy_nodes`：稳定统计分类
- 首次 `case_evidence`
- 当前 owner
- 第一个 `case_action`

原来的“知识漏洞 / 学习习惯 / 考试技巧”可保留为 `case_type`；具体模块通过受控 taxonomy 统一口径；真实表现仍用自由 title/description 表达。

### `03_知识闭环`
原有三阶逻辑：

**当堂订正 → 课后相似题 → 次课小测 → 清零 / 跨周**

软件不做一张“三阶表”，而是拆成：
- 当堂订正 → `interventions`
- 相似题巩固 → `interventions` + `case_actions`
- 次课小测 → `assessments`
- 每次状态变化 → `case_events`
- 未通过后的下一步 → 新 `case_action`

这样既保留三阶理念，又允许作文、习惯、考试策略使用不同干预路径。

同时明确：一次小测通过不自动等于案例永久关闭。

### `04_周度跟进`
原 Excel 一行一周，记录授课内容、旧问题整改、新问题、整改动作、复盘、下周重点。

**软件中不再要求教师重新填一份周表。**

系统从：
- lessons
- learning_cases
- case_events
- interventions
- assessments
- case_actions
- observations（后续）

自动生成周度摘要。

只有老师真正想补充的“本周综合判断”才允许作为可选说明，而不是必填。

### `05_顽固问题`
原 Excel 维护第二份“顽固问题跨周台账”。

软件取消独立事实表。

规则可提示某 learning_case 成为重点/长期问题，例如：
- 一段时间内多次验证失败；
- 连续多次未稳定；
- stable/closed 后 reopen；
- 长期存在却没有下一步行动。

由教师确认原因复盘和新的主行动。

好处：不会出现初诊表写“已解决”、顽固表仍写“跟进中”的冲突。

### `06_家校沟通`
V1.1 映射为 `parent_communications`。

联系方式不在每次沟通中复制，统一引用 guardian。

V1 先把教学闭环跑顺，不为了完整搬表提前建设家校主模块。

### `07_阶段复盘`
V1.1 拆成：
- 指标：从事实表自动计算；
- 总结：生成 report draft；
- finalized：冻结快照；
- 下一阶段重点：转化为已有/新案例的 case_actions。

报告不能成为另一套需要人工同步的“总台账”。

## 4. Excel 中值得保留的教学思想

必须保留：
- 三类问题初诊；
- 问题编号/可追踪思想；
- 三阶订正与再检测；
- 跨周跟进；
- 顽固问题原因复盘；
- 家校沟通；
- 阶段复盘；
- 不使用未经验证的复杂评分体系。

需要软件化改造：
- 一工作簿一学生 → 机构统一学生主档案；
- 一行一周 → 自动周度汇总；
- 顽固问题第二台账 → 同一案例派生提示；
- 固定三阶列 → 事件化干预/检测流程；
- “老师”当前值 → assignment 历史；
- “年级”当前值 → enrollment 历史；
- 自由分类字符串 → taxonomy + 自由标题；
- “下周重点”文字 → 可执行 case_action。

## 5. 课程不是原 Excel 的新增大台账

软件需要 `lesson`，只是为了把“这些教学事实发生在同一次课”关联起来，并支持课前/课后快速操作。

不要因此新增另一张“本课问题结果表”重复保存 intervention/assessment。

更不能因为存在 lesson 就顺势加入：
- 收费；
- 课消；
- 复杂排课；
- 销售 CRM。

这些不是当前产品核心。

## 6. V1 不做真实 Excel 自动导入

第一阶段先把数据库和工作流跑对，再开发导入器。

原因：
- 原型假设“一工作簿一学生一学科”；
- 软件已经拆分为多个关联对象；
- 过早写导入器会把临时字段结构固化进正式 schema。

等 schema 稳定后，再做：
1. Excel 预览；
2. 字段映射；
3. 分类映射；
4. 学生查重；
5. 导入校验；
6. 导入报告与回滚。

## 7. 产品验收问题

每增加一个页面、字段或数据库表，都应该问：

> **这是一个新的真实业务事实，还是同一事实的另一种展示/总结？**

如果只是另一种视图、周期统计或报告，优先做查询/View/报告，不要再让老师填写一遍。

还要再问：

> **这个字段能否帮助老师决定下一步，或帮助机构验证教学结果？**

如果答案都是否，优先删掉而不是保存“以后也许有用”。
